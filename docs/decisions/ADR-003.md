# ADR-003:向量能力用远程 embedding 供应商，不部署本地向量数据库

## Status: Accepted (2026-10-05)

## Background

框架的聚簇/召回依赖文本向量。`packages/backend/src/providers/embeddings.ts:19-21` 定义了可用性判断：

```ts
export function embeddingsAvailable(): boolean {
  return config.modelCallsEnabled && !!(credential("models", "EMBEDDING_API_KEY") ?? credential("models", "DASHSCOPE_API_KEY"));
}
```

没有配 key 时返回 `false`，`packages/backend/src/events/recall.ts:131-136` 走降级分支，用**字符 bigram 文字重合度**（`packages/backend/src/events/relate.ts:194-204`）：

```ts
export function lexicalSimilarity(a: string, b: string): number {
  const grams = (s: string) => { const chars = [...s.replace(/\s+/g, "")];
    return new Set(chars.map((_c, i) => chars.slice(i, i + 2).join("")).filter((g) => g.length === 2)); };
  const g = grams(a), h = grams(b);
  if (!g.size || !h.size) return 0;
  let inter = 0; for (const x of g) if (h.has(x)) inter++;
  return inter / Math.min(g.size, h.size);
}
```

降级阈值 `LEXICAL_MIN = 0.25`（`recall.ts:125`）。

**本项目的模型选型是 DeepSeek（OpenAI 兼容接口）。联网核实结论：DeepSeek 官方 API 不提供 `/embeddings` 端点** —— 其 OpenAI 兼容面只覆盖 `chat/completions`，没有 embeddings、没有 Assistants、没有 Files。

于是产生一个必须回答的问题：**只配DeepSeek 时，聚簇质量能不能接受？**

## Decision

**配置一个独立的远程 embedding 供应商：阿里云百炼 DashScope `text-embedding-v4`（1024 维）。不部署任何本地向量数据库。**

`.env`：

```dotenv
DASHSCOPE_API_KEY=<阿里云百炼 key>
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_DIMS=1024
```

`EMBEDDING_DIMS=1024` 不可变更（见 Consequences）。

## Consequences

### 正面

-聚簇召回质量达标。金融术语的同义/近义表达（「非农就业」vs「美国非农新增就业」、「缩表」vs「资产负债表缩量」、「COMEX 保证金上调」vs「纽约商品交易所提高保证金」）能被正确识别为同一件事
- 零运维：不需要额外的常驻进程、GPU、模型文件
- 成本可忽略：日均 200 条资料 ≈ 3M token/月 ≈ **¥1.5/月**
- 复用框架已有的 DashScope 分支（`embeddings.ts:12`的 `own ? "text-embedding-3-small" : "text-embedding-v4"`），**不需要改任何代码**

### 负面

- 引入第二个供应商（DeepSeek 生成 + DashScope 向量），两份 key、两份账单
- **多一个外部依赖**：DashScope 不可用时聚簇降级到文字重合度（静默降级，不报错）
- 数据出境/合规考量：资料标题与摘要会发给阿里云

### 内嵌坑（必须写进 Spec）

**内嵌坑 1（最重要）**：`EMBEDDING_DIMS` 变更会让所有已存向量作废。`embeddings.ts:15-16` 的注释明说「A vector of the configured size; a stored one of another size (`EMBEDDING_DIMS` changed) is computed again」——`VECTOR` 的 zod schema（`embeddings.ts:14`）会拒绝长度不匹配的存量向量并触发重算。**上线后禁止改这个值和 `EMBEDDING_MODEL`。**

**内嵌坑 2**：`embeddingsAvailable()` 依赖 `MODEL_CALLS_ENABLED`（`embeddings.ts:20`）。若为了省钱把 `MODEL_CALLS_ENABLED` 设成 `false`，**embedding 会跟着一起停**，聚簇静默降级到文字重合度，而系统不会有任何报错。调这个开关时要意识到它的连带影响。

**内嵌坑 3**：`text-embedding-v4` 是 1024 维。若将来换成 OpenAI `text-embedding-3-small`（默认维度 1536），维度会变 → 触发全量重算 + 一段时间的聚簇质量不稳定。**换供应商 = 一次性全量重算。**

**内嵌坑 4**：向量的相似度阈值与cosine 尺度绑定（`recall.ts:125` 注释：「shared bigrams are not on the cosine scale, so it has its own」）。**降级阈值 0.25 和 cosine 阈值不是同一个数**，不要试图统一调参。

## Alternatives Considered

| 方案 | 为什么拒绝 |
|---|---|
| 不配embedding，接受文字重合度降级 | [NG] 金融场景是bigram 降级的**最差用例**。同义不同词极多（缩表/资产负债表缩量、非农/非农就业/NFP、COMEX 保证金/纽约商品交易所保证金），漏召回会直接导致事件归组失败。`hot.ts` 的热度按「参与该事件的来源数」算（`MIN_PARTICIPANTS=2`），漏召回 → 来源数不足 → **真事件进不了热点榜** |
| 本地部署向量数据库（Milvus / Qdrant / Chroma） | [NG] 过度设计。框架的向量存储是 **PostgreSQL 内的 `real[]` 数组 + JS 侧 `cosine32` 计算**（`recall.ts:113-123`），**不是 pgvector**。MVP 语料量（10 万条以下）下 `Float32Array` 点积完全够用。加向量库只是多一个常驻服务和一份运维负担 |
| 本地跑 embedding 模型（llama.cpp + BGE-M3 / Qwen3-Embedding / DeepSeek 蒸馏模型） | [NG] 本机无 GPU（项目在 `D:\`，无独显信息），llama.cpp + 蒸馏模型要占 4-8GB 内存和一套进程管理。**且模型不同维度不同**（BGE-M3=1024、Qwen3-Embedding 可配 1024/768），会触发内嵌坑 1 的全量重算。远程 1-2 分钱/百万 token 更省事 |
| 加装 pgvector 扩展 | [NG] 需要改 `embeddings.ts` 的存储层与 `recall.ts` 的读取层（`real[]` → `vector(N)`），属改框架核心代码，超出「只改 `site/` + `industry/`」的范围。收益（10 万条以上更快）在 MVP 规模不成立 |
| 用 DeepSeek 的 chat 模型「顺便」算向量（拿 embedding 输出层） | [NG] 不受支持的做法。DeepSeek 官方只暴露 `chat/completions`，没有稳定 API 能取到 embedding；且 `embeddings.ts` 需要 `{ data: [{ index, embedding }] }` 的特定响应形状（`zod` 强校验），改适配 = 改框架代码 |
