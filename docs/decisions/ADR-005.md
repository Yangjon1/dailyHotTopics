# ADR-005: 单 DeepSeek 供应商分层，靠 per-step extra 参数而非换供应商

## Status: Accepted (2026-10-05)

## Background

框架把 AI 能力拆成若干**步骤**，每步可以用不同的模型。步骤名定义在 `tests/setup.ts:28-33`：

```ts
const STEP_MODELS: Record<string, [env: string, model: string]> = {
  prefilter: [...], score: [...], understand: [...], summarize: [...], structure: [...],
  group: [...], groupReview: [...], digest: [...], report: [...], translate: [...],
};
```

选型机制在 `site/models.ts`：`PRESETS` 定义具名模型（各带`baseUrlEnv`/`apiKeyEnv`/`extra`/`reasoningTokens`/`jsonMode`），`DEFAULTS: Record<string, string>` 按步骤名指定默认用哪个；没写的步骤落到 `default`（= `LLM_BASE_URL`/`LLM_API_KEY`/`LLM_MODEL` 指定的模型）。

需要判断的问题：**这些步骤的差异化需求，靠「换供应商/换模型」还是靠「同模型的参数差异」就能满足？**

各步骤的实际需求差异：

| 步骤 | 需求 | 对模型的 要求 |
|---|---|---|
| `prefilter` 预筛 | 高吞吐、低成本、判「要不要花钱分析」 | 便宜、快、格式稳定 |
| `score` 评分 | 理解力（要读懂事件实质份量）、输出严格单字段 JSON | 有推理能力、格式稳定 |
| `structure` / `summarize` | **中文表达质量**、标题与摘要的文学性 | 中文写作好 |
| `group` / `groupReview` 归组 | **必须严格按格式回答**（`group-batch.md` 要求纯 JSON，四选一 + confidence + note + selection），错格式会导致归组停摆 | 格式遵循性最高 |
| `digest` / `report` | 长文综述、周报月报总述 | 中文长文表达好 |
| `translate` 全文翻译 | 中译英| 翻译质量 |

框架原始示例用了 4 家供应商（DeepSeek / 智谱 GLM / 阿里 Qwen / 小米 MiMo）并为不同步骤配不同模型。本项目模型选型已定为 DeepSeek。

## Decision

**只用DeepSeek 一家。分层通过「同模型 + 不同 `extra` 参数」实现，不引入第二家供应商。**

`site/models.ts` 配置：

```ts
export const PRESETS: Record<string, ModelPreset> = {
  "deepseek-v4-flash": {
    service: "deepseek", model: "deepseek-v4-flash",
    baseUrlEnv: "DEEPSEEK_BASE_URL", apiKeyEnv: "DEEPSEEK_API_KEY",
    extra: { thinking: { type: "disabled" } }, jsonMode: true,
  },
  "deepseek-v4-flash-think": {
    service: "deepseek", model: "deepseek-v4-flash",
    baseUrlEnv: "DEEPSEEK_BASE_URL", apiKeyEnv: "DEEPSEEK_API_KEY",
    extra: { thinking: { type: "enabled" }, reasoning_effort: "high" },
    reasoningTokens: 4000, jsonMode: true,
  },
};

export const DEFAULTS: Record<string, string> = {
  group: "deepseek-v4-flash-think",        // 归组要稳定按格式回答
  groupReview: "deepseek-v4-flash-think",  // 归组复核同理
  // prefilter / score / understand / summarize / structure / digest / report / translate
  // 不写 → 落到 default = LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
};
```

`.env`：

```dotenv
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=<DeepSeek key>
LLM_MODEL=deepseek-v4-flash
LLM_EXTRA_JSON={"thinking":{"type":"disabled"}}
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_API_KEY=<同上，可复用>
```

## Consequences

### 正面

- 一份key、一份账单、**单一故障域**。DeepSeek 挂了整个站停摆（多供应商时至少评分还能跑）
- 零跨供应商的风格漂移：所有步骤的文风一致，摘要和综述读起来像一个人写的
- 成本最低。DeepSeek `deepseek-v4-flash` off-peak 输入 $0.22/百万、输出 $0.66/百万（联网核实 2026-10-05），比智谱/小米/阿里同档位都便宜
- 不用为4 家供应商各配 key、 各查一份限流、各处理一次 SDK 差异

### 负面

- **归组步骤（`group`）是单点故障**。`group-batch.md` 要求「只输出 JSON」，若thinking 模式下模型返回带解释的文本，`ModelOutputError` 会触发，归组停摆（`docs/deploy.md:165`：「归组用的模型回答不合格式时会停在那里」）。**归组是唯一对格式绝对敏感的步骤，也是唯一给了 thinking 模式的步骤——这是有意的权衡：宁可多花 token 也要格式稳定。**
- `thinking` 模式的延迟更高（2-5s+），归组会变慢。但归组只在「有相近报道」时触发（不是每条都调），影响面可控
- 放弃了一部分优化空间：如果评测发现 DeepSeek 的中文写作明显不如 Qwen，就得多一家供应商

### 内嵌坑（必须写进 Spec）

**内嵌坑 1（命名约定会骗人）**：`docs/deploy.md:103` 明确记录：「推理模型的额度改成明确配置。默认模型设 `LLM_REASONING_TOKENS`，具名模型写 `reasoningTokens`。**原来只有名字以 `-think` 结尾的具名模型会多给 4000，这个做法去掉了**」。

→ **名字以 `-think` 结尾不会自动获得额外额度**。必须显式写 `reasoningTokens: 4000`，否则归组的推理输出会被截断（表现为报错 `finish_reason=length`）。

**内嵌坑 2（模型名会退役）**：DeepSeek 的 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 退役（联网核实）。框架 `site/models.ts` 原有的 `deepseek-flash` 是**框架作者的内部别名**。改造时统一换成官方模型串 `deepseek-v4-flash`。写代码时**必须用显式模型名，不用 `latest` 之类的别名**。

**内嵌坑 3（`extra` 差异会被测试读到）**：`tests/setup.ts:40` 的 `pointModels()` 和 `tests/default-model.test.ts` 会检查每一步实际用的预设。改 `DEFAULTS` 后这些测试可能需要同步更新。

**内嵌坑 4（thinking 的 `extra` 形状）**：DeepSeek 的 `extra` 用 `{"thinking":{"type":"enabled"},"reasoning_effort":"high"}`。**智谱的形状不同**（`{"thinking":{"type":"enabled"},"reasoning_effort":"low"}` + `clear_thinking`）。不要照抄框架里智谱预设的 `extra` 结构。

## Alternatives Considered

| 方案 | 为什么拒绝 |
|---|---|
| 照搬框架的 4 供应商配置（DeepSeek + 智谱 GLM + 阿里 Qwen + 小米 MiMo） | [NG] 4 份 key、4 份账单、4 个故障域、4 种风格。为「可能更好」付确定成本，违反「不做过度设计」 |
| DeepSeek + 智谱 GLM 两家（按原`selection-score` 的重推理模型配置） | [!]️ 唯一有说服力的理由是 `glm-5.3-flash-selection` 原本就为「评分」步骤调了 `reasoning_effort: "high"`。但 DeepSeek 的 `deepseek-v4-flash` 在 thinking 模式下同样有推理能力，**没有证据表明这一步必须换供应商**。建议先用单供应商跑 `scripts/eval-selection.ts`，若评分质量不达标再引入第二家（`site/models.ts` 支持随时加 preset，无需改框架） |
| 本地部署 DeepSeek 开放权重 | [NG] `deepseek-v4-flash` 是 284B 总参/ ~13B 激活的 MoE，本机无 GPU。`deepseek-v4-pro`（1.6T）更是完全不可能。本地跑要么换蒸馏小模型（质量下降）、要么需GPU（不在方案内） |
| 用 DeepSeek 的 reasoning 模型做所有步骤 | [NG] `prefilter`（每条都要跑的高频低成本步骤）开thinking 会让成本和延迟翻倍，而预筛任务本身不需要推理 |
