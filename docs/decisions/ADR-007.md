# ADR-007: 每日价格快照走站点端点，不做 modules/quotes 看板

## Status: Superseded (2026-10-05)

> **本 ADR 已被用户裁决推翻。** 原决策「价格看板做 `modules/quotes/`，MVP 不做」的前提是「每日快照不进入MVP」。
> 用户随后明确裁决「**做：每日价格快照**」，它被升为 P0（Spec §2 的 F6）。
> 因此**「MVP 不做」的前提不成立**，本 ADR 作废。
>
> **替代决策见 ADR-010**（快照读侧走站点端点 `GET /api/site/quotes`，不建表、不做模块）。
> 保留本文件以记录决策轨迹：规格演进中 ADR 与 Spec 互相矛盾是真实发生过的教训。

## Background

读者是投资/决策视角。没有价格锚点，「金价上涨 2%」这条新闻无法判断轻重——涨2% 是大事还是噪声？「COMEX 保证金上调至 8%」意味着什么？需要一个近 30 日的价格参照。

框架的 `docs/architecture.md:62-75` 定义了「模块」机制：框架里没有、只有你这个站要的功能（比如「一个专门的榜单或监控页」），做成 `modules/<名字>/`，是一个名为 `@aihot/<名字>` 的 npm 包。

关键约束（`docs/architecture.md:75`）：「**框架的代码不导入任何模块，只读这三份清单**，所以合并本仓库以后的更新时，不容易和你自己的功能冲突」。

需要判断：**价格看板做成模块还是做进框架？**

## Decision

**做成 `modules/quotes/` 站专属模块，MVP 阶段不做（列入完整版），最小实现只做「近 30 日收盘价 + 涨跌幅 + 关键统计指标」的静态展示。**

三个插口的职责划分（按 `docs/architecture.md:64-74`）：

| 文件 | 职责 |
|---|---|
| `module.ts` | `defineModule({ name: "quotes", pages: [{ path: "quotes", file: "pages/quotes.tsx" }], apiPaths: [/^\/api\/v1\/quotes/] })` —— 纯数据，**每个进程都读**（含 web build） |
| `server.ts` | ① `http` 插口注册路由与静态资源（用 `apps/api/src/routes/static.ts` 的 `sendFile`，它处理类型/ETag/缓存头/404，文件名自校验）；② `ModuleQueue` 插口挂 pg-boss 定时任务拉价格；③ 自己的 `migrations/` 建表；④ 价格数据获取与规范化 |
| `web.tsx` | 页面注册 + 导航项 + 主题页/后台部件 |

注册到三份清单（`docs/architecture.md:75`）：

```ts
// site/modules/index.ts   —— 列地址
// site/modules/server.ts   —— 列后端
// site/modules/web.ts      —— 列网页
// site/package.json       —— dependencies 里加 "@aihot/quotes": "*"
```

## Consequences

### 正面

- **框架保持可合并**。上游更新不会与本项目冲突（框架不导入模块）
- 不改 `packages/backend/` 任何文件
- 价格表归自己管，schema 可自由演进（框架的 `articles`/`facts`/`stories` 表不需要知道「价格」这个概念）
- pg-boss 定时任务通过 `ModuleQueue` 插口接入，复用框架现有的队列（`packages/backend/src/jobs/queue.ts:64` 的 `PgBoss`），**不新建进程**

### 负面

- **行情数据来源必须自己解决**。框架的 `packages/backend/src/sources/` 全部是**文本内容采集**：`json-list.ts:186-196` 产出的 `Candidate` 是 `{url, title, author, publishedAt, excerpt, bodyText, raw}`，**没有「时序行情」概念**（`raw` 里只有 `externalId` 一个自定义字段）。所以价格要走**模块自己的迁移建表 + 模块自己的采集**，不能复用 `sources/`
- 依赖上游数据源（交易所/数据商 API）的稳定性与授权，这是模块自己的运维负担
- 增加一个 workspace（`package.json:10` 的 `workspaces` 已含 `modules/*`），`npm ci` 多装一个包

### 内嵌坑（必须写进 Spec）

**内嵌坑 1（`apiPaths` 是正则，不是路径前缀）**：`packages/contracts/src/modules.ts` 定义的是 `apiPaths?: RegExp[]`。写 `["/api/v1/quotes"]` 不会生效——**必须是 `/^\/api\/v1\/quotes/`**。

**内嵌坑 2（迁移的命名约束）**：`docs/architecture.md:79` 要求「按完整文件名排序执行，并以完整文件名记录是否已经执行；**同一完整文件名不能出现在两个目录中**」，且「从 `0055` 起，每个文件只放一条允许在线执行的语句」。模块的迁移在 `modules/quotes/migrations/`，与 `database/migrations/` 一起执行——**编号不要与主目录重复**。

**内嵌坑 3（静态文件名必须自校验）**：`docs/architecture.md:73` 明确「用 `sendFile` 发出（类型、ETag、缓存头和 404 都由它处理，**文件名自己校验**）」。这是路径穿越防护，不能省。

**内嵌坑 4（Dockerfile 需加一行）**：`docs/architecture.md:75`：「用 Docker 部署的，在 `Dockerfile` 里照着其他包加一行 `COPY modules/<名字>/package.json modules/<名字>/`」。虽然本项目走Windows 本机（ADR-001），但**保留 Dockerfile 可用性**是低成本的——将来上服务器不用改。

**内嵌坑 5（`tests/architecture.test.ts` 会检查模块边界）**：该文件用 `git ls-files`（第 148 行）做架构约束检查。新增模块后要确认 `npm run typecheck` 和 `npm test` 里的架构测试仍然通过。

## Alternatives Considered

| 方案 | 为什么拒绝 |
|---|---|
| 做进 `packages/backend/src/` | [NG] 改框架核心代码，与上游冲突；且违背项目「只改 `site/` 和 `industry/`」的约定。模块机制的存在就是为了避免这个 |
| 复用 `sources/json_list` 采价格 | [NG] **技术障碍**。`json-list.ts:180-182` 要求每条数据必须有 `title` 和 `url`（`if (!title || !url) continue`），且 `urlTemplate` 走 `{path}` 模板渲染。行情数据的「标识」是 `(品种, 时间)`，不是 URL。且同一 URL 上的数据会持续变化 —— 框架的去重逻辑怎么处理（待验证项 V1）尚未确认。**强行复用会引入一个未验证的去重假设** |
| 不做价格看板 | [!]️ 这是 ADR 的**第三选项**，MVP 阶段实际采纳。代价：读者判断不了「涨 2%」的权重，站点在「投资决策视角」这个核心定位上打折。缓解：MVP 阶段靠 `modules/quotes` 之外的最小手段——在摘要里带上原文提到的绝对价位（由ADR-006 的数字三件套规则保证单位正确） |

### 明确不做（out-of-scope）

K 线图、实时行情、撮合引擎、持仓模拟、涨跌停计算、跨品种价差套利。`modules/quotes` 只做静态日频价格展示。
