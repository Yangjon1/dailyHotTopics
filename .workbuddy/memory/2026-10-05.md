```json
{ "itemSelector": "div.flex.flex-col", "linkSelector": "a[href^='/news/article/']",

```

**新的静默失效模式（比 403 更隐蔽）**：
- 403 → 抓取报错，能发现

## 2026-10-06 切换到全 Docker 环境

**用户的疑问**：只在 Docker 里看到 pg，前 后端环境在哪。**答案：之前是混合形态**（数据库在 Docker 容器、api/worker/web 是 Windows 上的 Node 进程），而且昨晚那些进程已随会话结束停掉。**现已切到项目自带的全 Docker 方案**。

**切换步骤与踩的坑**：

## 2026-10-07 推送成功（git 认证踩坑）
**根因**：`git config --show-origin` 显示 `credential.helper=helper-selector`，来自 WorkBuddy 内置 PortableGit 的 `etc/gitconfig`（**系统级**）。`helper-selector` 只是个**选择器**，在非交互 shell 里不会弹选择菜单 → 直接报 `could not read Username`。
**你 `git-credential-manager github login` 已经成功了**（`github list` 显示 `Yangjon1`，`get` 能取到 token），**但 git 压根没调用它**。
**修法（仓库级，不动全局）**：
```bash
git config credential.helper ""
git config --add credential.helper "C:/Users/23165/.workbuddy/binaries/PortableGit/versions/1.2.0/mingw64/bin/git-credential-manager.exe"
```
**教训：登录成功 ≠ git 会用它。** 「凭据管理器里有账号」和「git 配置指向它」是两件事——**遇到 `could not read Username` 时先 `git config --show-origin --get-all credential.helper` 看它到底指向谁**，别以为登录了就够了。
